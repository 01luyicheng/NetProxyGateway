# 安全性设计（v1/v2 基线）

本文件给出可执行的安全基线，约束控制面（API/MQTT）与数据面（SOCKS5/隧道/转发）的最小安全要求。

相关实现与链路说明见：
- [服务端中转](server-socks5-relay.md)
- [通信协议](./07-communication-protocol.md)
- [VPN 集成（v2）](integration-vpn-socks5.md)

## 9.1 传输层安全

### 9.1.1 加密要求

- 对公网通信必须使用 TLS（建议 TLS 1.2+，优先 TLS 1.3；以实际平台/库支持为准）。
- MQTT 如启用：必须使用 MQTT over TLS（通常为 `8883/TCP` 或受控的 TLS 承载）。
- 工程师到云端 SOCKS5 入口：必须是加密链路（例如置于受控 TLS 终止之后，或通过本地 TLS 包装/SSH 隧道接入）。

### 9.1.2 证书与信任

- 证书固定（pinning）属于增强项：可在威胁模型要求更高时启用。
- 无论是否 pinning，必须具备证书轮换与故障回滚策略，避免“证书更新导致全量不可用”。

## 9.2 身份认证与授权

### 9.2.1 配对码与防爆破

- 配对码必须短期有效（例如 ≤ 10 分钟）且一次性使用。
- 必须具备尝试次数限制、冷却与短期封禁（按 `source_ip` + `account/engineerId` 维度）。

### 9.2.2 会话令牌

- 工程师侧 SOCKS5 鉴权应使用**短期、可撤销的会话令牌**（避免长期口令复用）。
- 设备凭证必须可撤销/可轮换；不得硬编码在 App 包内。

### 9.2.3 最小权限与目标过滤

- 默认仅允许访问 RFC1918 IPv4 + 端口白名单。
- 明确拒绝：loopback、`0.0.0.0/8`、链路本地（包含 `169.254.169.254` 元数据地址）、广播/多播等特殊地址。
- 如需支持“客户内网使用公网段”，必须通过控制面显式下发 allowlist（带版本/签名/过期），并记录审计。

## 9.3 控制面消息安全（MQTT/隧道指令）

### 9.3.1 主题 ACL

- 每设备独立凭证。
- 仅允许发布/订阅自身主题（如 `device/{deviceId}/...`），禁止宽泛通配权限。

### 9.3.2 anti-replay 与幂等

控制指令必须包含：
- `message_id`（去重/幂等）
- `expires_at`（时钟窗校验）
- `sig`（若启用消息签名则必须校验）

接收端必须实现：去重缓存（TTL 覆盖时钟偏移窗与过期时间）、过期拒绝、重复投递幂等。

## 9.4 敏感数据与隐私

### 9.4.1 WiFi 凭证

- 不得通过 MQTT/API/日志传输或记录明文 WiFi 密码。
- 设备侧如需保存 WiFi 凭证，使用 Android Keystore/系统安全存储；并在内存中尽快清理。

### 9.4.2 日志与审计

- 不记录明文 token/密码/DNS 查询内容/应用层 payload。
- 审计日志记录最小元数据（操作者、deviceId、目标 ip:port、结果码、时长/字节数）并脱敏。
- 调试需要更详细日志时，必须“临时开关 + 到期自动关闭 + 审计留痕”。

## 9.5 安全检查清单

| 检查项 | 说明 |
|-------|------|
| TLS | 公网链路强制 TLS（建议 TLS 1.2+） |
| MQTT TLS | MQTT 如启用必须 TLS + 设备级 ACL |
| anti-replay | 控制消息具备 `message_id/expires_at` 去重与时钟窗校验 |
| 限流/封禁 | 配对码与鉴权失败具备限速、冷却与短期封禁 |
| 目标过滤 | RFC1918 allow + 特殊地址硬拒绝 + 例外 allowlist 可审计 |
| 日志脱敏 | 不记录凭证与 payload；审计字段固定脱敏 |
