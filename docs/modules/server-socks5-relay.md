# 服务端 SOCKS5 中转设计（v1：云端入口 + 设备反向隧道）

本模块用于指导服务端实现“工程师公网访问 → 设备所在 WiFi 内网目标”的最小可闭环链路。

v1 的关键假设：设备通常在 NAT/无公网入站环境，**不依赖工程师直连手机端口**。

```text
Engineer -> Cloud SOCKS5 Entry -> Reverse Tunnel -> Device -> WiFi LAN Target
```

## 范围与目标

**v1 交付目标**
- 工程师使用通用 SOCKS5 客户端连接云端入口。
- 通过明确的“会话绑定机制”将该 SOCKS5 连接绑定到一个 `deviceId`，并将 SOCKS5 `CONNECT`（TCP/IPv4）流量转发至该设备。
- 设备在 WiFi 上连接内网目标并做双向字节转发。

**v1 非目标**
- 不做 VPN 全局接管、不做透明代理。
- 不承诺 `BIND` / `UDP_ASSOCIATE`、不承诺 IPv6。

---

## 组件与职责

**1) 控制面（Auth/API）**
- 工程师登录/鉴权、下发“可访问设备列表/权限”。
- 配对/绑定设备、签发设备侧凭证。

**2) Cloud SOCKS5 Entry（数据面入口）**
- 对工程师提供 SOCKS5 服务端。
- 解析 SOCKS5 握手与 CONNECT 目标地址。
- 根据认证结果 + 会话绑定信息（`deviceId`）路由到指定设备的隧道会话，并桥接流量。

**3) Reverse Tunnel Gateway（隧道网关，可与入口同进程）**
- 维护设备 → 云端的长连接。
- 为每个设备提供多路复用通道（多个并发 CONNECT 共享连接）。

**4) 设备侧 Agent（Android App 内）**
- 主动连云，建立隧道并保持在线。
- 收到“打开到目标 (ip:port)”请求后，在 WiFi Network 上发起 TCP 连接并转发。

## 端口与可达性矩阵

端口具体数值可配置，但语义必须全项目一致。v1 建议：

| 端口/协议 | 由谁监听 | 谁来连接 | 用途 | 备注 |
|---|---|---|---|---|
| `1080/TCP` | 云端 | 工程师 | SOCKS5 入口 | 工程师唯一入口 |
| `443/TCP` | 云端 | 工程师/设备 | HTTPS API | 配对/鉴权/管理 |
| `8883/TCP` | 云端 | 设备 | MQTT over TLS（可选） | 若采用 MQTT 做控制面 |

设备侧不需要任何公网入站端口。

补充说明：反向隧道承载可以复用 `443/TCP`（例如 `wss://.../tunnel` 或其他受控的 TLS 承载），避免额外开放端口；是否复用由服务端实现与部署策略决定，但“设备侧主动出站”这一可达性假设不变。

## 会话与数据流

### 设备上线（隧道会话建立）

1) 设备通过控制面获取设备凭证（短期/可撤销）。
2) 设备主动连接隧道网关，建立长连接并完成双向认证。
3) 云端注册：`deviceId -> tunnelSession`。

### 工程师连接（SOCKS5）

#### 设备选择与会话绑定（v1 必须定义）

通用 SOCKS5 协议本身不包含 `deviceId` 字段，因此 v1 必须定义一个对通用客户端友好的绑定方式。

推荐的最小闭环方案：
1) 工程师先通过 HTTPS API 创建 SOCKS 会话（携带 `deviceId`），服务端返回短期可撤销的 `socks_session_token`（例如有效期 ≤ 15 分钟）。
2) 工程师在 SOCKS5 客户端中配置认证字段：
	- username：`deviceId`
	- password：`socks_session_token`
3) 云端入口在 SOCKS5 USERNAME/PASSWORD 鉴权阶段完成：令牌校验 → 授权检查（engineerId 是否允许访问该 deviceId）→ 将该 TCP 会话绑定到 deviceId（直到连接关闭）。

该方案的优点是：不需要定制客户端协议，且把“设备选择”与“授权”收敛到服务端控制面。

1) 工程师连接云端 SOCKS5 入口并完成认证。
2) 工程师发起 SOCKS5 CONNECT 到目标 `dst_ip:dst_port`。
3) 云端将该 CONNECT 作为“打开子流”的请求发往指定设备会话。
4) 设备在 WiFi 上连接内网目标，返回成功后开始双向拷贝。

## 鉴权、授权与安全基线

### 传输加密（必须）

- 工程师到云端入口：必须加密传输（例如将入口放在 TLS 终止之后，或实现 SOCKS5 over TLS）。
- 设备到云端隧道：必须加密传输（TLS）。

补充约束（为避免凭证暴露）：
- **禁止**在公网直接暴露“明文 SOCKS5”。若入口监听 `1080/TCP`，必须位于受控网络边界内，或放在 TLS 终止之后（SOCKS5 over TLS / 四层 TLS 代理 / SSH 隧道等）。
- 控制面（HTTPS API）、隧道面（TLS）、MQTT（TLS）三条链路均视为“承载凭证/控制指令”的高敏通道：不得允许明文传输与降级。

文档不对 TLS 版本、证书固定策略做超前承诺；以实际实现为准，但必须满足“凭证不明文暴露、链路可抗窃听”。

### 凭证与密钥管理（必须）

- SOCKS5 认证：优先使用**短期、可撤销的会话令牌**（例如由控制面签发、有效期 ≤ 15 分钟），避免长期 username/password 在客户端侧被复用与泄露。
	- 令牌建议绑定：`engineerId`、允许的 `deviceId` 列表（或单 device）、可选 `source_ip`/`user_agent` 指纹、过期时间。
	- 令牌泄露处置：服务端应支持即时吊销、强制下线当前 SOCKS5 会话。
- 设备凭证：必须可撤销/可轮换；禁止把长期密钥硬编码在 App 包内；不得通过日志/崩溃上报输出。
- MQTT（如启用）：每设备独立凭证 + 主题级 ACL（仅允许 `device/{deviceId}/...`）；禁止共享账号与过宽的通配订阅/发布权限。

### 认证与授权（必须）

- 工程师认证：控制台签发短期访问凭证。
- 设备认证：设备凭证可撤销、可轮换。
- 授权：服务端必须判断“工程师是否可访问该 deviceId”。
- 目标限制：服务端与设备端都要执行目标过滤（双重约束），默认仅允许 RFC1918 IPv4 + 端口白名单。

目标过滤的最低可执行口径（建议默认拒绝）：
- 仅允许：RFC1918 IPv4（`10/8`、`172.16/12`、`192.168/16`）+ 明确端口白名单。
- 明确拒绝（无条件）：loopback `127/8`、`0.0.0.0/8`、链路本地 `169.254/16`（包含 `169.254.169.254` 等元数据地址）、广播/多播（`224/4`、`255.255.255.255`）、以及任何“解析为公网 IP”的目标。
- 如需支持“客户内网使用公网段”的例外，必须通过控制面**显式下发 allowlist CIDR**（带版本号/签名/过期时间），并在审计中标记为例外来源。

### 抗爆破/抗重放（必须）

- 配对码/临时码：必须有尝试次数限制、冷却、封禁策略。
- 控制/隧道消息：必须包含 `message_id/nonce` + 过期时间；服务端做去重与时钟窗校验。

补充可执行细则（避免“写了但落不了地”）：
- 去重缓存：按（`deviceId` + `message_id`）存储，TTL 至少覆盖 `max_clock_skew + (expires_at - now)`；重复消息直接拒绝或幂等返回。
- 时钟窗：允许的时钟偏移（skew）需给出固定值（例如 2~5 分钟）；超窗消息拒绝并计入风控。
- MQTT QoS 导致的重复投递必须视为常态：去重/幂等是必需能力，不是优化项。
- 封禁（建议）：
	- 对配对码/登录/SOCKS5 认证失败：按 `source_ip` + `account/engineerId` 维度限速（例如 Token Bucket），超过阈值进入冷却；持续失败触发短期封禁（例如 10~30 分钟），并输出审计事件。

### 审计与隐私

- 审计记录：工程师主体、deviceId、目标 (ip:port)（可脱敏/按段）、开始/结束时间、结果码。
- 不记录明文凭证；除协议接入所需的 TLS 终止外，不对业务内容做额外解密/审计与留存；仅解析 SOCKS5 握手所需的最小元数据。

补充可执行原则：
- 脱敏规则需固定：例如 `dst_ip` 仅保留 /24（或哈希后存储），“端口”保留原值；禁止记录 DNS 查询内容、应用层 payload、HTTP Header/Cookie。
- 保留期与访问控制：审计日志应有默认保留期（例如 7~30 天，按合规要求配置）与最小权限访问；禁止把审计日志直接暴露给普通业务后台。
- 例外处理：调试场景如需更细粒度日志，必须走“临时开关 + 到期自动关闭 + 审计留痕”。

## 中转限制与资源保护

- 限速：对每设备/每工程师连接执行带宽上限（Token Bucket 或等价策略），避免带宽被单会话耗尽。
- 连接数上限：限制单设备并发 CONNECT 数与单工程师并发连接数；超限时拒绝新建连接。
- 超时：空闲超时、建立连接超时、隧道心跳超时。

---

## 可观测性（v1 最小集）

- 指标：在线设备数、活跃隧道数、活跃 CONNECT 数、建连失败率、转发字节数、拒绝原因分布（鉴权失败/超限/目标不允许）。
- 日志：按 connection_id/tunnel_stream_id 关联，便于排障；日志字段需脱敏。

---

## v1 范围取舍

- 仅支持 SOCKS5 `CONNECT`（TCP/IPv4）。
- 不支持 `BIND`、`UDP_ASSOCIATE`、不支持透明代理。
- VPN/tun2socks 集成属于 v2（见 [integration-vpn-socks5.md](integration-vpn-socks5.md)）。
